# camera_speed_test

Прошивка для **Arduino Nano** (PlatformIO): измерение задержки в цепочке **светодиод → фотоприёмник** и **калибровка уровней АЦП** с выводом на **ST7789**. Интерфейс на экране — **английский** (компактные строки под узкий дисплей). Подробная **распиновка** — в [`pins.md`](pins.md).

## Сборка и прошивка

```bash
pio run -t upload
```

Параметры порта и скорость — в [`platformio.ini`](platformio.ini).

## Стек

- **MCU:** ATmega328P (Nano)
- **Дисплей:** ST7789 SPI (Adafruit ST7735/ST7789 + GFX)
- **Настройки:** `include/Config.h` (тайминги, пины, размер экрана)

---

## Назначение

Оценка **задержки между переключением светодиода и сменой сигнала на фотоприёмнике** на одной стендовой сборке (в перспективе — вспомогательное средство для оценки *glass-to-glass* по видеотракту при аккуратном сопоставлении сценария).

**Железо в коде:**

- **Свет** — биколорный LED (красный / синий / погашен), два вывода МК.
- **Приём** — **A1**: по `pins.md` — **фототранзистор** с подтяжкой к 5 В: темно — **выше** код АЦП, ярче — **ниже** код.
- **Кнопка** — **D2**, `INPUT_PULLUP`.

## Управление (жесты)

| Жест | Условие (`ButtonInput` + `Config.h`) | С главного меню | Во время режима |
|------|--------------------------------------|-----------------|-----------------|
| Короткое одиночное | короткое отпускание без второго нажатия в окне | Главное меню | То же — выход в меню, LED выкл. |
| Двойное короткое | два коротких отпускания подряд, ≤ `kDoubleClickMaxGapMs` | Старт **калибровки** | — |
| Долгое | удержание ≥ `kLongPressMs`, затем отпускание | Старт **замера задержки** | — |

Антидребезг: `kButtonDebounceMs`. «Короткое» ограничено сверху `kShortPressMaxMs`.

## Калибровка (ADC, красный / синий)

**Цель:** показать по каждой фазе **Min / Max / Average напряжения** на входе АЦП (пересчёт из кода при `kAdcVrefVolts` = 5 В), пока горит то **красный**, то **синий** канал LED.

Важно: в текущей версии результаты калибровки **идут только на экран**; режим задержки **не** подхватывает сохранённые пороги из этой калибровки — пороги для замера строятся **заново** в коротком прогреве (см. ниже).

**Алгоритм:**

1. Выполняется `kCalibPhaseCount` фаз (по умолчанию **4**).
2. Фазы `0, 1, 2…`: чётная — **красный**, нечётная — **синий**.
3. Длительность одной фазы — `kCalibPhaseDurationMs` (по умолчанию **5 с**).
4. АЦП опрашивается с периодом не реже `kCalibSamplePeriodMs`; за фазу накапливаются min/max код и среднее.
5. После каждой фазы на дисплей выводятся **Min / Max / Avg (В)** по **только что завершённой** фазе; затем переключение цвета и сброс накопления.
6. В конце LED **гаснутся**, показывается экран завершения калибровки.

**Смысл:** оценить размах и стабильность при R/B (спектр и ток могут слегка менять отклик датчика).

## Измерение задержки (мс)

**Цель:** за окно **`kLatencySessionMs`** (после прогрева, по умолчанию **15 с** активного мигания) много раз измерить время от **переключения LED** до **пересечения порога АЦП** фотоприёмником; итог — **Min / Max / Average** в **миллисекундах**.

### Прогрев (пороги)

Без опоры на предыдущую калибровку в памяти:

1. **Темновой уровень:** LED выключен, интервал `kLatencyWarmupDarkMs` → средний код `latDarkAvg_` (обычно **выше**).
2. **Световой уровень:** красный включён, `kLatencyWarmupLitMs` → средний код `latLitAvg_` (**ниже**).

Порог между состояниями:

- `mid = (latDarkAvg_ + latLitAvg_) / 2`
- нижний порог: `mid - kLatencyThresholdHysteresisAdc`
- верхний: `mid + kLatencyThresholdHysteresisAdc`  

Гистерезис уменьшает дребезг; при вырождении пороги слегка разводятся в коде (`Application.cpp`).

### Мигание и отсчёт времени

- Старт: **красный** включён.
- Каждые `kLatencyBlinkHalfPeriodMs` (полупериод, по умолчанию **250 ms**): **красный ↔ выключено** (контраст «свет / нет»).
- В момент каждого переключения фиксируется **`micros()`** (`latEdgeT0Us_`):
  - LED **включён** — ждём **падение** АЦП ниже нижнего порога;
  - LED **выключен** — ждём **рост** выше верхнего порога.
- Задержка выборки: **`micros() - latEdgeT0Us_`** (мкс); в статистику пишутся успешные события.
- Если за `kLatencySensorTimeoutUs` фронта нет — такт пропускается.

### Итог

Число успешных выборок, min/max/sum в мкс → на экран min/max/avg в **мс**. При нуле выборок отображаются нули.

## Ограничения

- Измеряется задержка **команда на пины LED → ответ АЦП** на стенде, а не полная цепочка камера–кодек–дисплей.
- Пороги замера задержки берутся из **короткого прогрева**, не из длинной калибровки R/B.
